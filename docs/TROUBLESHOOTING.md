# Troubleshooting

Use this index when Northwind shows a known symptom. Diagnose read-only first, preserve request IDs and exact commit SHAs, and follow the linked canonical runbook before any mutation. Stop whenever the active identity, project, environment or recovery path is ambiguous.

| Observable symptom                                              | Safe read-only diagnosis                                                                                                                            | Likely cause                                                                                            | Safe next step                                                                                       | Stop or escalate when                                                                            | Reference                                                                                                             |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Hostinger placeholder page                                      | Check `/api/live`, `/api/ready` and `/api/health`; inspect the configured entry and deployment artifact list                                        | Managed application is not using root `app.js`, or the compiled API/web assets are absent               | Follow the artifact and entry checks in the canonical deployment runbook                             | DNS, application, project or rollback target is uncertain                                        | [NW-LL-010](LESSONS_LEARNED.md#nw-ll-010), [Hostinger runbook](HOSTINGER_DEPLOYMENT.md)                               |
| Temporary Hostinger `503`                                       | Poll readiness for the bounded interval used by the live-release verifier and inspect sanitized deployment logs                                     | Cold start, build activation or a real readiness failure                                                | Allow the documented readiness window; investigate the request ID if readiness does not recover      | Assets are missing, Firestore is unavailable, or the served SHA is wrong                         | [Hostinger runbook](HOSTINGER_DEPLOYMENT.md), [INC-001](incidents/INC-001-hostinger-release-verification.md)          |
| GitHub staging check receives `403`                             | Verify the exact SHA, readiness, no-store responses and assets read-only from an independent network; inspect the failed job for a consistent `403` | A GitHub-hosted runner IP was temporarily rejected before the request reached the application           | Rerun only the failed job on a fresh GitHub runner after independent verification passes             | The fresh runner also fails, the response is not consistently `403`, or any release fact differs | [NW-LL-017](LESSONS_LEARNED.md#nw-ll-017), [Hostinger runbook](HOSTINGER_DEPLOYMENT.md#release-and-rollback)          |
| Health endpoint reports the wrong SHA                           | Compare the full health SHA with `git rev-parse`, `git ls-remote` and the approved staging workflow run                                             | Wrong deployment, stale build or untrusted release metadata                                             | Re-run the read-only live-release verifier for the expected SHA                                      | Any branch moved, metadata is missing, or production differs from approved staging               | [NW-LL-011](LESSONS_LEARNED.md#nw-ll-011), [NW-LL-012](LESSONS_LEARNED.md#nw-ll-012)                                  |
| Production or `main` is ahead of permanent `staging`            | Fetch both branches, compare ancestry and inspect the intervening commits, pull-request bases and live health SHAs                                  | A documentation, portfolio or application pull request targeted `main` instead of `staging`             | Freeze production changes, preserve legitimate work and reconcile it through a reviewed staging PR   | The commits contain unknown data, secrets, schema changes, divergent history or failed checks    | [NW-LL-020](LESSONS_LEARNED.md#nw-ll-020), [ADR 0006](adr/0006-exact-sha-release-promotion.md)                        |
| Deployment reports a dirty tree                                 | Run `git status --short` and `git diff --name-only`; inspect the build-state classification                                                         | Hostinger normalized `package-lock.json`, or a real tracked file changed                                | Accept only the explicitly tested lockfile normalization; investigate every other path               | An application, workflow, configuration or script file differs                                   | [INC-001](incidents/INC-001-hostinger-release-verification.md), [ADR 0006](adr/0006-exact-sha-release-promotion.md)   |
| Backup cron cannot find Node or npm                             | Inspect sanitized cron output, the fixed wrapper and the documented Hostinger Node path                                                             | Cron has a minimal `PATH` and does not inherit the interactive shell runtime                            | Use the dependency-free runner through the explicit Node 22 binary in the runbook                    | The token path, app root or environment mapping differs from the reviewed wrapper                | [NW-LL-013](LESSONS_LEARNED.md#nw-ll-013), [Hostinger runbook](HOSTINGER_DEPLOYMENT.md#private-hostinger-backup-cron) |
| API reports `FIRESTORE_UNAVAILABLE`                             | Check health/readiness, sanitized logs and the request ID; verify the selected project and quota read-only                                          | Firestore outage, quota exhaustion or repository initialization failure                                 | Preserve the failed operation and retry only after repository readiness returns                      | The active Google identity or project is not the approved one                                    | [NW-LL-009](LESSONS_LEARNED.md#nw-ll-009), [Architecture](ARCHITECTURE.md)                                            |
| Workspace says “Northwind could not load” while health is ready | Run `npm run data:integrity` with the approved Firestore environment and inspect only schema paths and issue codes                                  | A stored record violates a shared schema, so the all-store bootstrap fails closed                       | Use the reviewed compatibility parser, then dry-run `npm run data:migrate:company-canonical`         | Identity, project, backup/PITR, exact SHA or migration plan is not verified                      | [NW-LL-019](LESSONS_LEARNED.md#nw-ll-019), [INC-004](incidents/INC-004-malformed-company-bootstrap.md)                |
| A known company, person or route is missing from search         | Inspect the relevant paginated request and confirm `q` plus selected route filters are sent; query it without writing                               | Browser is filtering a loaded page, stale client code is served, or the normalized query does not match | Refresh current application state and verify the server-backed response                              | The record is absent from Firestore or identity data conflicts                                   | [NW-LL-002](LESSONS_LEARNED.md#nw-ll-002), [INC-003](incidents/INC-003-paginated-company-search.md)                   |
| Totals change when a page loads                                 | Compare the UI with `/api/routes/metrics` and authenticated workspace-wide summary state                                                            | A component derived global totals from the visible page                                                 | Use server-derived metrics and full bootstrap summary values                                         | Server metrics and integrity-derived totals disagree                                             | [NW-LL-003](LESSONS_LEARNED.md#nw-ll-003), [INC-003](incidents/INC-003-paginated-company-search.md)                   |
| Save returns `409 VERSION_CONFLICT`                             | Fetch the current record and compare its version with the submitted `If-Match` value                                                                | Another browser saved a newer version                                                                   | Explain the conflict, refresh, reapply the intended edit and submit once against the current version | Retrying would discard or duplicate another person's work or activity history                    | [Architecture](ARCHITECTURE.md#records-and-concurrency), [Known issues](KNOWN_ISSUES.md)                              |
| Browser shows older data after another save                     | Check the workspace revision request, tab visibility and current bootstrap/page query                                                               | The open browser has not invalidated its cached query yet                                               | Focus or refresh the application and retry the read-only query                                       | Firestore does not contain the saved state or revisions stop advancing                           | [Known issues](KNOWN_ISSUES.md), [AI agent handbook](AI_AGENT_HANDBOOK.md)                                            |
| Git UI reports changes but the worktree looks clean             | Run `git status --short`, compare local/remote SHAs and inspect left/right commit counts                                                            | Stale remote-tracking metadata or a branch comparison badge rather than uncommitted files               | Refresh remote references, then repeat the comparisons                                               | `git status` reveals real staged, modified or untracked files                                    | [NW-LL-015](LESSONS_LEARNED.md#nw-ll-015)                                                                             |
| Backup is stale, locked or invalid                              | Run `npm run backup:hostinger:status` and authenticated backup diagnostics; inspect lock age without deleting it                                    | Missed cron, active run, malformed stale lock or invalid archive                                        | Preserve existing archives; follow the documented stale-lock and verification procedure              | A fresh lock exists, fewer valid copies would remain, or a token/key may be exposed              | [INC-002](incidents/INC-002-backup-recovery-hardening.md), [Data recovery](DATA_RECOVERY.md)                          |
| Restore validation fails                                        | Use `backup:verify` and `backup:restore:validate` against a copy; compare IDs, hashes and relationships                                             | Wrong recovery key, corrupt archive, schema mismatch or conflicting target database                     | Stop and select another verified archive or empty temporary target                                   | The target is production/default, contains unexpected records, or key custody is uncertain       | [ADR 0007](adr/0007-encrypted-hostinger-recovery.md), [Data recovery](DATA_RECOVERY.md)                               |
| Firestore emulator or visual snapshots differ by machine        | Confirm Node 22, Java 21, Chromium installation, OS-specific snapshots and a clean checkout                                                         | Runtime drift or platform-specific rendering rather than product behavior                               | Reproduce with repository-pinned commands and inspect the actual rendered difference                 | Updating a snapshot would hide an unexplained accessibility, layout or data change               | [AI agent handbook](AI_AGENT_HANDBOOK.md#verification-tiers), [CONTRIBUTING](../CONTRIBUTING.md)                      |

## Escalation record

When no row resolves the symptom, record the environment, exact SHA, sanitized request ID, read-only observations and failed verification command. Do not include credentials, cookies, tokens, private keys, password hashes or production record contents. A material outage or failed release should use the [incident template](incidents/README.md).
